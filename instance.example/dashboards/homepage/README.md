# Homepage portal config

The glanceable link board served at **`:3000`** (fronted by NPM at `control.<domain>`). One file per concern
(modularity): `services.yaml` (tiles), `settings.yaml` (layout), `widgets.yaml` (header strip), `bookmarks.yaml`.
On a brand-new node `kontroll-init --fresh` scaffolds this directory into the private `instance/` overlay and
fills the `services.yaml` sentinels with your mgmt IP + domain.

## Login posture — unauthenticated by design

**Homepage is an unauthenticated, read-only tile board.** This is deliberate, not a gap:

- **No auth** — gethomepage (the upstream) ships no login; it is a static link/widget board.
- **No actuation** — every tile is an `href:` link or a GET-only widget. Homepage cannot change a device or
  the stack. Nothing here is a control surface (that is the onboard-GUI on `:8443`, which *is* authenticated).
- **No secret in the served config** — tiles are `href:` + `description:` only; live-widget API keys (if you add
  them) are `{{HOMEPAGE_VAR_*}}` placeholders injected from SOPS at deploy, never written into this YAML —
  each is a `homepage_var_<name>` key of the `dashboards` domain, rendered into Homepage's own
  `docker/.env.homepage` (the portal never receives the stack `.env`).
- **mgmt-bound, never WAN** — the `:3000` container binds all interfaces (the documented **SECURITY.md C3**
  NPM-fronted exception); the mgmt boundary is enforced at the NPM / firewall layer, at `control.<domain>` on the
  mgmt VLAN. **Keep `:3000` on the mgmt VLAN.** If you have not put NPM in front yet, front it with your reverse
  proxy or bind it to your mgmt IP — do not expose it to the WAN.

## `services.yaml` — hand-authored + a generated Fleet group

- **Above the markers:** your control-plane tiles (the `__MGMT_IP__`/`__DOMAIN__` template, filled by
  `kontroll-init --fresh`) and any of your own services. Edit freely.
- **The `Fleet` group** is generated between the markers
  `# >>> kontroll fleet (generated by scripts/gen-homepage.py …) >>>` … `# <<< kontroll fleet (generated) <<<`.
  `scripts/gen-homepage.py` (run by `deploy-stack`) fills it from your onboarded fleet — one `href:`+`description:`
  tile per onboarded host (the enabled modules × your inventory, the same fleet the GUI Fleet panel shows),
  rewritten on each deploy. **Do not hand-edit between the markers** — those changes are overwritten on regen, and
  the `:8443` Homepage editor flags the group read-only (you may reposition the whole block, never its tiles). Add
  fleet devices by onboarding, not by editing tiles. A tile derives `https://<mgmt-addr>` by default; a class can
  steer its own tile with an optional `homepage: {scheme, port, icon}` block in `modules/<key>/module.yml`.
