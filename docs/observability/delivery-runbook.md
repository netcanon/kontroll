## 0. The binding delivery invariants (apply to every phase)

These come straight from the real code and the directives; the implementer must satisfy all of them in **the same commit** as the behaviour:

1. **Docstring-or-die.** `tests/check-test-docs.py:13-15` ASTs every `tests/**/test_*.py` and fails the build on any `def test_*` lacking a docstring. Every test below ships with the docstring text given verbatim — it states *what it verifies* AND *the failure it guards against*.
2. **Generated-never-hand-maintained, machine-enforced.** `tests/validate.sh:72` runs `gen-observability.py --check`. Any **new** generated artifact (a generated prometheus job file) needs its **own** `--check` step added to `validate.sh` in the same commit, replicating the want/have/set-math/orphan-prune from `gen-observability.py:main()` lines 89-116.
3. **LF lockfile + GENERATED header.** Generated files are written `newline="\n"` with the `# GENERATED by … Do NOT edit by hand` header (`gen-observability.py:30-32, 112`). Any new generator copies this exactly and ends artifacts in `.generated.<ext>`.
4. **Fail-closed dispatch.** Today an unknown `via` silently falls through to the host branch (`gen-observability.py:53`). The new dispatcher **must** `sys.exit(2)` (loud) on a metrics entry naming a method with no `telemetry/<name>.yml` descriptor — never emit an empty or wrong target. This replaces the closed-enum's accidental safety with explicit safety, pinned by a test.
5. **Byte-for-byte migration.** The host-agent and pve descriptors must reproduce the *current* generated output exactly. Acceptance for the refactor commit is **`git diff prometheus/targets/` is empty** after a non-`--check` run. A label-order or label-set change is a live-config change, not a refactor.
6. **No new trust boundary in the MVP.** Phases 1–4 are pure generators/loaders + Ansible roles run by the operator/Semaphore. They cross **no** new auth/audit boundary. The API/GUI actuation (Phase 7+) is explicitly gated behind the separately-tracked privileged-mutation enablement (`SECURITY.md` C9:198-199) and **does not run Ansible or docker from the network surface** — it proposes data only.
7. **Doc-sync is part of done.** Each phase lists its exact `CLAUDE.md` Documentation-Sync rows. Reciprocal "See also" links land in the same commit.

**Dispatcher sketch (`gen-observability.py`, replacing `_entries`):**

```python
from kontroll import catalog   # standalone-safe: catalog imports only stdlib+yaml on this path

_METHODS = None
def _methods():
    global _METHODS
    if _METHODS is None:
        _METHODS = {m["name"]: m for m in catalog.load_telemetry()}
    return _METHODS

# Legacy shim: existing {via,port,job} entries map to a method so module.yml can migrate lazily.
def _resolve_method(met):
    if "method" in met:
        name = met["method"]
    elif met.get("via") == "proxy":
        name = "pve"            # the only proxy class today (job: proxmox)
    else:
        name = "host_node"
    m = _methods().get(name)
    if m is None:
        sys.exit("gen-observability: metrics entry names unknown telemetry method %r "
                 "(add telemetry/%s.yml)" % (name, name))   # FAIL CLOSED — invariant #4
    return m

def _entries(met, group, hosts):
    m = _resolve_method(met)
    rows = []
    for name, ip in sorted(hosts.items()):
        if m["kind"] == "proxy-exporter":
            rows.append(([ip], {"host": name}))                       # device addr; relabel proxies it
        else:                                                         # host-agent
            rows.append((["%s:%s" % (ip, m["port"])], {"group": group, "host": name}))
    return rows
```

> Note: `metrics_files` (lines 69-82) keys the output path on `met["job"]` today. After migration a `{method: …}` entry has no `job` key, so the loop must read the job from the resolved method: `job = _resolve_method(met)["job"]`. **Collision guard (major from self-review):** if two metrics entries on one class resolve to the same `(job, key)` path, `sys.exit` loudly rather than silently overwrite — pinned by `test_duplicate_job_for_one_class_fails_loud`.

**`load_telemetry()` (`catalog.py`, mirrors `load_vectors`):**

```python
def load_telemetry():
    """telemetry/<method>.yml — drop-in telemetry method descriptors (the metrics analogue of
    load_backends). Sorted by `order` so node_exporter is one row, not the pipe."""
    out = []
    if os.path.isdir(paths.TELEMETRY_DIR):
        for fn in sorted(os.listdir(paths.TELEMETRY_DIR)):
            if fn.endswith((".yml", ".yaml")):
                with open(os.path.join(paths.TELEMETRY_DIR, fn), encoding="utf-8") as fh:
                    out.append(yaml.safe_load(fh))
    return sorted(out, key=lambda m: m.get("order", 99))
```

```python
def observe(body: ObserveIn, request: Request,
            principal: Principal = Depends(require_token), cat: Catalog = Depends(get_catalog)):
    plan = build_observability_plan(body.key, body.method, body.params, body.dashboard_gnet,
                                    methods=cat.telemetry_methods)   # PURE, writes nothing
    if not body.apply:
        return {"applied": False, "plan": _observe_view(plan), "run_id": principal.run_id}
    # NAMES never values — the exporter secret var name only:
    audit_action(request, principal, "observe-apply",
                 "key=%s method=%s creds=%s" % (body.key, body.method,
                                                sorted(plan["creds_to_set"].keys())))
    applied = apply_observability_plan(plan)        # writes module block + regen targets ONLY
    return {"applied": True, "run_id": principal.run_id, **applied}
```

**run_id correlation (the audit-silo gap, delivery self-review):** route the GUI opt-in **through the API** (which mints `run_id` at the boundary, `auth.py:40`, and is fail-closed on audit) rather than the GUI's 4-field fail-open `_audit`. The enact step (Semaphore play) receives `-e kontroll_run_id=<principal.run_id>` so the GUI click → plan → playbook is greppable end-to-end via the `_log-run-id.yml:19` mechanism. The audit line is **`observe-apply`** with `key/method/creds=<var-names>` — **never** the SNMP community or API key value.
